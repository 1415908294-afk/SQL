# 第一阶段验收记录

日期：2026-10-22（Asia/Shanghai）。运行环境：Windows，Node 24.20.0，DuckDB 原生 1.3.2、DuckDB-Wasm 包 1.30.0 / 引擎 1.3.2。

## 通过的程序验证

- 7个课程阶段，每阶段3题，共21题，六张模拟业务表。
- 数据行数：users 120；signup_events 120；ai_conversations 528；channels 4；orders 40；activity_events 678。
- 21条标准 SQL 在原生数据库执行通过，写入 expected.json。
- 21条 SQL 在实际 Wasm 引擎中经过分词、prepare、执行和 Arrow 转换，结果全部与原生标准结果一致，含日期、金额、CTE、窗口、JOIN、留存和封闭漏斗。
- 原生与 Wasm 的 READ_ONLY 均拒绝 DELETE、UPDATE、DROP、CREATE 和 INSERT；最终 users 仍为120行。
- Wasm 拒绝外部文件、HTTP CSV读取和重新启用外部访问。
- 多语句、试图逃逸子查询、WITH后写操作均被阻止。
- 字符串内分号、中文、美元引号、开头/结尾注释正确处理。
- 判题覆盖无序结果、指定排序、重复行多重集、NULL与字符串区分、数值误差及截断拒绝。
- 活跃事件与用户无孤立关联；TypeScript 与 Vite 生产构建通过。

## 手动验收路径

1. `npm ci` → `npm run dev`，打开终端 Local 地址。
2. 首页点击第一堂课，等待 DuckDB 就绪；默认查询运行后出现10行用户，日期为 YYYY-MM-DD。
3. 提交默认查询，应通过并增加进度；刷新后记录仍在。
4. 修改为 `SELECT COUNT(*) AS total_users FROM users;`，选择第2题再填入并提交，应返回120且通过；错别名时应提示列名问题。
5. 运行 `WITH u AS (SELECT * FROM users) SELECT COUNT(*) AS n FROM u;`，应返回120。
6. 运行 DELETE、双语句、外部 read_csv，应报错；再次查询用户数仍为120。
7. 在第8题运行标准答案，应显示 revenue=1725，检查金额不被显示成172500。
8. 展开/收起提示和答案，格式化编辑器代码，导出 CSV 并检查列名与中文。
9. 浏览七阶段课程与六表字典，标记已读，导出/导入进度备份。
10. 浏览器宽度调整到390px和1440px，检查横向溢出、表格滚动与导航。
